# AirNote / 空书

AirNote 的 React + TypeScript + Vite 网页项目。当前包含 M0 第一版低延迟技术尖峰。

当前版本用于验证“摄像头帧 → 本地单手追踪 → 捏合状态机 → EMA → Canvas Ink”的输入链路，不代表完整 P0。所有其他入口均为禁用状态或明确标记“暂未实现”。

## 环境要求

- Node.js 24.x
- npm 11.x

## 安装

```bash
npm install
```

## 本地启动

```bash
npm run dev
```

Vite 默认启动地址为 `http://localhost:5173/`。如果端口被占用，终端会显示实际地址。

打开页面后，需要由用户点击“启用摄像头”才会请求权限。首发验证浏览器为桌面 Chrome 和 Edge。

## 工程检查

```bash
npm run typecheck
npm test
npm run build
```

## 当前范围

已完成：

- React、TypeScript、Vite 工程配置
- 按产品模块划分的目录结构
- 640×480、30 FPS 理想约束的主动摄像头授权与关闭
- 本地托管的 MediaPipe Hand Landmarker、单手追踪和镜像坐标
- 两帧捏合落笔、速度自适应松开断笔、三帧丢手断笔和 250ms 中断保护
- 抬笔阈值 0.42；比初始 0.48 更早识别松开，减少尾部多余线段
- 慢速松开单帧停止；快速移动时需连续3帧确认，确认期间不追加点，避免关键点抖动造成断触或尾线
- 方向自适应 EMA：水平前进轴 0.62、垂直抖动轴 0.18，其他方向 0.5
- 仅在 X/Y 位移比达到 4.0 时启用水平专用抑抖，避免斜线被误判成阶梯
- MediaPipe 置信阈值为检测0.6、存在0.5、追踪0.35，增强快速移动连续性
- Canvas 使用轻量中点二次曲线连接采样点，只改变显示，不改写轨迹数据
- 2 CSS 像素抽样和 Canvas 2D 临时 Ink；快速但连续追踪的移动仍会连线
- 摄像头、手势、推理 FPS、耗时和错误状态反馈
- 未实现操作的禁用状态
- 状态机、轨迹、摄像头生命周期和错误处理测试

未实现：

- 正式书写区域与捏合校准
- 正式 Stroke 数据与鼠标降级绘图
- Stroke、分组、卡片、连接和历史
- 本地保存、导入导出
- OCR、后端、账号、云同步
- Glow、Particle 等视觉效果

## 隐私边界

页面加载时不会请求摄像头权限；只有用户主动点击后才启用。视频和关键点只在浏览器运行时内存中处理，不录制、不保存、不上传。MediaPipe WASM 与模型均从项目本地加载，不包含 API 密钥或外部服务配置。
